# 验证与兼容性

本文说明如何检查源码、构建应用，以及星月池已验证和待验证的范围。构建成功不代表所有设备、网络与安全场景均已通过测试。

## 本地检查

在源码根目录运行：

```powershell
npm ci
npm test
npm run audit:source
```

`npm ci` 使用锁文件安装依赖；`npm test` 运行 Node 自动化测试；`audit:source` 检查公开源码清单、明显凭据、个人路径和资源元数据。联网时可额外运行 `npm audit` 查询依赖的已知漏洞，结果以查询时的漏洞数据库为准。

修改图标或随附资源时，可分别运行 `npm run build:icons` 和 `npm run build:vendor`，检查生成结果、相关许可证和源码审计是否一致。

## 平台构建检查

按 [Windows 构建说明](WINDOWS-BUILD.md)准备环境后，运行：

```powershell
npm run build:windows
```

检查便携版、安装版及 `build-report.json` 是否生成，核对报告中的源码与打包内容哈希。报告验证打包内容一致性，不保证不同机器生成的 EXE 逐字节相同。手动启动开发版时，应使用独立测试数据，并检查文件池、设置、共享开关、本机文件窗口及退出重启行为。

按 [Android 构建说明](ANDROID-BUILD.md)准备 JDK 和 Android SDK 后，运行：

```powershell
npm run build:android
```

构建脚本执行 APK 签名和 ZIP 对齐验证。安装前应确认包名、版本、签名和许可文件符合用途；默认临时签名不适合持续覆盖升级。

准备源码归档时，在不含 `.git`、依赖和构建输出的独立源码副本中运行：

```powershell
npm run audit:source -- --strict-clean
```

不要为通过严格审计删除正常工作仓库的 Git 历史。源码 ZIP 应检查解压后的文件集合和逐文件 SHA-256，防止漏文件或夹带运行数据。

## 尚未验证的范围

- 真实 Android 手机、平板的安装、系统分享入口、后台传输、通知和系统文件选择器行为。
- Windows 安装器执行后的系统集成，以及全部受支持系统版本的兼容性。
- 蓝牙硬件互传、校园网隔离、移动数据与跨网络中继连接。
- 公网部署的配置与运行安全、长期连续运行和生产负载。

功能依赖设备、权限或网络条件时，应在目标环境中补充测试，并记录版本、环境、步骤、结果与限制。尚未测试的项目不应标为通过。

源码审计使用允许清单、人工检查和特定检测规则，无法保证发现全部秘密或安全漏洞；锁定依赖版本也不能替代持续维护。安全问题的报告方式见 [安全与隐私](../SECURITY.md)。
